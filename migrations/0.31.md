# Migrating to Phronomy 0.31

Phronomy 0.31 adds explicit schema delivery and durable transcript reads, and
fixes ownership and release of one-shot and Agent Tool children. Review these
compatibility boundaries when upgrading from 0.30.1.

## Stored executions

New structured executions store output-contract version 2 with `schema_delivery`
and use AgentExecution envelope 0.3. The schema remains saved and locally
validated even with `schema_delivery: :none`; omitting native schema delivery is
an explicit application choice, not an automatic fallback or output repair.

Deploy compatible readers before writing these records. Older readers reject
0.3, including completed executions; do not downgrade a store containing them.
Version 0.31 still reads envelope 0.2 and existing version-1 native output
contracts without rewriting them merely on read. Existing free-text records do
not acquire a schema retroactively. See the
[structured-output persistence contract](../architecture/structured-output-and-scope.md#failure-and-persistence).

## One-shot Agent ownership

`Agent.run_once` owns its fresh Agent and ephemeral Store through
`Agent.open_scope` and releases the live Agent before returning. A reusable
Agent must instead use `create`/`load` or an explicit ownership scope.

When release succeeds, the original invocation value or exception is preserved.
Unsafe or failed release raises `Agent::ScopeCleanupError`, retaining the result,
primary error, failed owners and scope. Resolve the release condition before
retrying `error.scope.release!`; this does not repeat model or Tool work.
Approval waits, physical work, independent leases, retention and recovery still
prevent unsafe release. No records are purged and no shared Store or Runtime is
shut down. See [single-invocation ownership](../architecture/structured-output-and-scope.md#single-invocation-ownership).

## Agent-backed Tools

Both synchronous `execute` and asynchronous `call_async` now invoke the child
through `invoke_async`. A subclass that overrides only `invoke` no longer
changes the synchronous Tool path. Move the intended customization to the
asynchronous entry point and preserve its TaskResult contract.

Each call owns its fresh child and ephemeral Store until invocation and physical
work have finished and safe release completes. Normal return includes release;
successful output conversion remains unchanged. Waiting does not consume an
OffloadPool worker solely to join the child.

A release failure raises `Phronomy::Tools::Agent::CleanupError` with code
`tool.agent_cleanup_failed`. It retains `child_agent`, `agent_id`, `result`,
`primary_error` and `cleanup_error`; the cause is the primary failure when one
exists, otherwise the release failure. Resolve the release condition, then retry
`error.child_agent.unload_async` for release only. These live handles are
process-local and are not reconstructed from saved error diagnostics.

Cleanup failures are also diagnosed after observer cancellation and are not
hidden by ordinary Tool error suppression. Completed runtime wiring no longer
retains released children through generated callbacks, temporary tracker context
or completed participation changes. Session ownership, commit/readback ordering,
physical leases and recovery guards remain unchanged. See the
[Agent Tool child lifetime contract](../architecture/agent-tool-child-lifetime.md).

## Live-provider limits

LM Studio/gpt-oss PEG output parsing remains unresolved. Known-error
identification and one bounded retry do not establish the root cause or prevent
recurrence. The existing evidence distinguishes a failed call stopped after two
POSTs from a separate application invocation that succeeded on its first POST;
it does not show recovery by retry within one call.

The DX1/DX2 normal live path, streaming, Tool use and history restoration remain
unverified in that environment. Source review, offline tests and CI support this
release; they do not establish live LLM acceptance. See the
[LM Studio policy and evidence limits](../architecture/lm-studio-output-failures.md).
