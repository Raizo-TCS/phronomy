# Phronomy — Implementation Roadmap

## 1. Phase Overview

Implementation is divided into 4 phases. Each phase provides standalone value in a "stacked value" structure.

| Phase | Name | Estimated Duration | Value Provided |
|---|---|---|---|
| Phase 1 | Core Chain | 2–3 weeks | Prompt → LLM → parser pipeline |
| Phase 2 | Graph Runtime | 3–4 weeks | State graph-based agent workflow |
| Phase 3 | Memory & Persistence | 2–3 weeks | State persistence, memory management, complete Rails integration |
| Phase 4 | Multi-Agent & Observability | 3–4 weeks | Multi-agent, observability, MCP support |

---

## 2. Phase 1: Core Chain

### Target Components

- `Phronomy::Runnable` module
- `Phronomy::Chain::PromptTemplate`
- `Phronomy::Chain::LLMChain`
- `Phronomy::Chain::Sequential`
- `Phronomy::OutputParser::Base`, `JsonParser`, `StructuredParser`
- `Phronomy::Tool::Base` (thin wrapper around RubyLLM::Tool)
- `Phronomy::Configuration`
- `Phronomy::Railtie` (basic configuration only)

### Milestone

```ruby
# Code that works when Phase 1 is complete
prompt = Phronomy::Chain::PromptTemplate.new(
  system_template: "You are a helpful assistant.",
  template: "Answer: <%= question %>"
)
llm    = Phronomy::Chain::LLMChain.new(model: "gpt-4o")
parser = Phronomy::OutputParser::JsonParser.new

chain = prompt >> llm >> parser
result = chain.invoke(question: "What is Ruby?")

# Streaming
chain.stream(question: "Explain Ruby") { |c| print c }

# Batch
results = chain.batch([{ question: "Ruby?" }, { question: "Rails?" }])
```

### Test Requirements

- RSpec unit tests: independent tests for each component
- VCR (vcr gem) for recording and replaying LLM API calls
- Provider mocks for unit testing
- PromptTemplate: ERB rendering, variable injection
- LLMChain: streaming, chain with tools
- OutputParser: JSON parsing, error handling

## 3. Phase 2: Graph Runtime

### Target Components

- `Phronomy::Graph::State` module
- `Phronomy::Graph::StateGraph`
- `Phronomy::Graph::CompiledGraph`
- `Phronomy::Runtime::Pregel` (simple version: sequential execution only)
- `Phronomy::Agent::Base`
- `Phronomy::Agent::ReactAgent`
- `Phronomy::Checkpointer::Base`
- `Phronomy::Checkpointer::InMemory`
- `Phronomy::Interrupt` exception

### Milestone

```ruby
# Code that works when Phase 2 is complete
class SearchState
  include Phronomy::Graph::State
  field :query,  type: :replace
  field :result, type: :replace
end

graph = Phronomy.graph(SearchState) do |g|
  g.add_node(:search) { |s| { result: WebSearch.call(s.query) } }
  g.add_node(:answer) { |s| { result: LLM.answer(s.result) } }
  g.add_edge(:search, :answer)
  g.set_entry_point(:search)
end

compiled = graph.compile(
  checkpointer: Phronomy::Checkpointer::InMemory.new,
  interrupt_before: [:answer]
)

begin
  compiled.invoke({ query: "Ruby 3.4?" }, config: { thread_id: "t1" })
rescue Phronomy::Interrupt => e
  # Resume after approval
  compiled.resume(thread_id: "t1")
end
```

### Test Requirements

- StateGraph: adding nodes, defining edges, compiling
- CompiledGraph: sequential execution, conditional branching, loop detection
- Interrupt: complete suspend → save → resume flow
- Checkpointer::InMemory: save, load, history
- Agent::Base: invoke, loop including tool calls

## 4. Phase 3: Memory & Persistence

### Target Components

- `Phronomy::Memory::Base`
- `Phronomy::Memory::WindowMemory`
- `Phronomy::Memory::SummaryMemory`
- `Phronomy::Memory::ActiveRecordMemory`
- `Phronomy::Checkpointer::ActiveRecord`
- `Phronomy::Checkpointer::Redis` (optional)
- `Phronomy::ActiveRecord::ActsAs`
- Rails generators (install, agent, tool)
- `CompiledGraph#stream` (node event streaming)

### DB Schema

```ruby
# migration generated by generate phronomy:install

create_table :phronomy_checkpoints do |t|
  t.string  :thread_id,      null: false
  t.string  :graph_id
  t.string  :completed_node
  t.string  :interrupted_at
  t.text    :state_json,     null: false
  t.integer :step,           default: 0
  t.timestamps
  t.index :thread_id
  t.index [:thread_id, :created_at]
end

create_table :phronomy_checkpoint_histories do |t|
  t.string  :thread_id,      null: false
  t.string  :completed_node
  t.string  :interrupted_at
  t.text    :state_json,     null: false
  t.integer :step,           default: 0
  t.timestamps
  t.index :thread_id
end

create_table :phronomy_messages do |t|
  t.string :thread_id,  null: false
  t.string :role,       null: false
  t.text   :content,    null: false
  t.text   :tool_calls_json
  t.string :model
  t.timestamps
  t.index :thread_id
end
```

### Milestone

```ruby
# Phase 3 complete: persistent agent works in a Rails app
class SupportAgent < Phronomy::Agent::Base
  model "claude-3-5-sonnet-20241022"
  instructions "You are a support agent."
  tools SearchKB, CreateTicket
end

# Rails controller
class ApiController < ApplicationController
  def chat
    agent = SupportAgent.new
    result = agent.invoke(
      params[:message],
      config: {
        thread_id: "user_#{current_user.id}",
        memory: Phronomy::Memory::ActiveRecordMemory.new
      }
    )
    render json: { response: result[:output] }
  end
end

# ActionCable streaming
compiled.stream(input, config: { thread_id: "t1" }) do |event|
  ActionCable.server.broadcast("agent_#{user_id}", event)
end
```

## 5. Phase 4: Multi-Agent & Observability

### Target Components

- `Phronomy::Crew`
- `Phronomy::Task`
- `Phronomy::Tool::McpTool` (MCP protocol support)
- `Phronomy::Tracing::Base`
- `Phronomy::Tracing::NullTracer`
- `Phronomy::Guardrail::Base`
- `Phronomy::Guardrail::InputGuardrail`
- `Phronomy::Guardrail::OutputGuardrail`
- `Phronomy::Runtime::Pregel` (parallel node execution)
- `phronomy-tracing` optional gem (OpenTelemetry / Langfuse)

### Milestone

```ruby
# Phase 4 complete: multi-agent and observability work

# === Crew ===
crew = Phronomy::Crew.new(
  agents: { researcher: ResearcherAgent.new, writer: WriterAgent.new },
  tasks: [
    Phronomy::Task.new(description: "Research", agent_role: :researcher),
    Phronomy::Task.new(description: "Write", agent_role: :writer)
  ],
  process: :sequential
)
crew.kickoff(topic: "AI Agents")

# === MCP ===
mcp_tool = Phronomy::Tool::McpTool.from_server("stdio://./mcp-server", tool_name: "web_search")

# === Guardrail ===
class NoPersonalDataGuardrail < Phronomy::Guardrail::InputGuardrail
  def check(input)
    if input.match?(/\d{4}-\d{4}-\d{4}-\d{4}/)
      fail!("Credit card numbers cannot be submitted")
    end
  end
end

agent = MyAgent.new
agent.add_input_guardrail(NoPersonalDataGuardrail.new)

# === Tracing (optional gem) ===
# Gemfile: gem 'phronomy-tracing'
Phronomy.configure do |c|
  c.tracer = Phronomy::Tracing::LangfuseTracer.new(
    public_key: ENV["LANGFUSE_PUBLIC_KEY"],
    secret_key: ENV["LANGFUSE_SECRET_KEY"]
  )
end
```

## 6. Testing Strategy

### 6.1 Unit Tests

Test each component independently with VCR cassettes and mocks.

```ruby
# spec/phronomy/chain/llm_chain_spec.rb
RSpec.describe Phronomy::Chain::LLMChain do
  let(:chain) { described_class.new(model: "gpt-4o-mini") }
  
  it "returns text for string input", vcr: "llm_chain/basic" do
    result = chain.invoke("Hello")
    expect(result).to be_a(String)
    expect(result).not_to be_empty
  end
  
  it "yields each chunk when streaming", vcr: "llm_chain/streaming" do
    chunks = []
    chain.stream("Hello") { |c| chunks << c }
    expect(chunks).not_to be_empty
  end
end
```

### 6.2 Integration Tests

```ruby
# spec/integration/graph_with_checkpointer_spec.rb
RSpec.describe "Graph with Checkpointer" do
  it "suspend and resume flow works" do
    graph = build_simple_graph
    compiled = graph.compile(
      checkpointer: Phronomy::Checkpointer::InMemory.new,
      interrupt_before: [:step2]
    )
    
    expect { compiled.invoke({ input: "test" }, config: { thread_id: "t1" }) }
      .to raise_error(Phronomy::Interrupt)
    
    result = compiled.resume(thread_id: "t1")
    expect(result.output).not_to be_nil
  end
end
```

### 6.3 Test Coverage Goals

| Phase | Unit Coverage | Integration Tests |
|---|---|---|
| Phase 1 | >= 90% | Chain pipeline end-to-end |
| Phase 2 | >= 85% | Graph execution, interrupt/resume |
| Phase 3 | >= 85% | Persistence across restart |
| Phase 4 | >= 80% | Multi-agent coordination |
