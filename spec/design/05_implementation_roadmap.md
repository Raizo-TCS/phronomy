# Phronomy — Implementation Roadmap

## 1. Phase Overview

Implementation is divided into 3 phases. Each phase provides standalone value in a "stacked value" structure.

| Phase | Name | Estimated Duration | Value Provided |
|---|---|---|---|
| Phase 1 | Graph Runtime | 3–4 weeks | State graph-based agent workflow |
| Phase 2 | Memory & Persistence | 2–3 weeks | State persistence, memory management, complete Rails integration |
| Phase 3 | Multi-Agent & Observability | 3–4 weeks | Multi-agent, observability, MCP support |

---

## 2. Phase 1: Graph Runtime (COMPLETED)

### Implemented Components

- `Phronomy::WorkflowContext` module
- `Phronomy::WorkflowRunner` (state-machine execution engine)
- `Phronomy::Workflow` DSL
- `Phronomy::Agent::Base`
- `Phronomy::StateStore::Base` / `InMemory` / `ActiveRecord` / `Redis`

### Milestone (current API)

```ruby
class SearchContext
  include Phronomy::WorkflowContext
  field :query,  type: :replace
  field :result, type: :replace
end

app = Phronomy::Workflow.define(SearchContext) do
  initial :search
  state :search, action: ->(s) { s.merge(result: WebSearch.call(s.query)) }
  state :answer, action: ->(s) { s.merge(result: LLM.answer(s.result)) }
  wait_state :awaiting_approval
  after :search, to: :answer
  after :answer, to: :awaiting_approval
  after :awaiting_approval, to: :__finish__
  event :approve, from: :awaiting_approval, to: :__finish__
end

Phronomy.configure { |c| c.default_state_store = Phronomy::StateStore::InMemory.new }

# First run — halts at :awaiting_approval
state = app.invoke({ query: "Ruby 3.4?" }, config: { thread_id: "t1" })
# state.halted? => true

# Resume after approval
app.send_event(:approve, config: { thread_id: "t1" })
```

### Test Requirements

- Workflow DSL: state definition, transitions, conditional routing
- WorkflowRunner: sequential execution, guard-based branching, loop detection
- wait_state: suspend → save → resume via send_event
- StateStore::InMemory: save, load
- Agent::Base: invoke, loop including tool calls

## 4. Phase 3: Multi-Agent & Observability

### Target Components

- `Phronomy::Tool::McpTool` (MCP protocol support)
- `Phronomy::Tracing::Base`
- `Phronomy::Tracing::NullTracer`
- `Phronomy::Guardrail::Base`
- `Phronomy::Guardrail::InputGuardrail`
- `Phronomy::Guardrail::OutputGuardrail`
- `phronomy-tracing` optional gem (OpenTelemetry / Langfuse)

### Milestone

```ruby
# Phase 3 complete: multi-agent (Agent-as-Tool), observability

# === Multi-Agent (Agent-as-Tool) ===
class ResearchTool < Phronomy::Tool::Base
  description "Research a topic"
  param :topic, type: :string, desc: "Topic to research"
  def execute(topic:) = ResearcherAgent.new.invoke(topic)[:output]
end

class OrchestratorAgent < Phronomy::Agent::Base
  tools ResearchTool, WriteTool
  instructions "Coordinate research and writing."
end

OrchestratorAgent.new.invoke("Write a blog post about Ruby 3.4")

# === MCP ===
mcp_tool = Phronomy::Tool::McpTool.from_server("stdio://./mcp-server", tool_name: "web_search")

# === Guardrail ===
class NoPersonalDataGuardrail < Phronomy::Guardrail::InputGuardrail
  def check(input)
    if input.match?(/\d{4}-\d{4}-\d{4}-\d{4}/)
      fail!("Credit card numbers cannot be submitted")
    end
  end
end

agent = MyAgent.new
agent.add_input_guardrail(NoPersonalDataGuardrail.new)

# === Tracing (optional gem) ===
# Gemfile: gem 'phronomy-tracing'
Phronomy.configure do |c|
  c.tracer = Phronomy::Tracing::LangfuseTracer.new(
    public_key: ENV["LANGFUSE_PUBLIC_KEY"],
    secret_key: ENV["LANGFUSE_SECRET_KEY"]
  )
end
```

## 5. Testing Strategy

### 6.1 Unit Tests

Test each component independently with VCR cassettes and mocks.

```ruby
# spec/phronomy/chain/llm_chain_spec.rb
RSpec.describe Phronomy::Chain::LLMChain do
  let(:chain) { described_class.new(model: "gpt-4o-mini") }
  
  it "returns text for string input", vcr: "llm_chain/basic" do
    result = chain.invoke("Hello")
    expect(result).to be_a(String)
    expect(result).not_to be_empty
  end
  
  it "yields each chunk when streaming", vcr: "llm_chain/streaming" do
    chunks = []
    chain.stream("Hello") { |c| chunks << c }
    expect(chunks).not_to be_empty
  end
end
```

### 6.2 Integration Tests

```ruby
# spec/integration/workflow_spec.rb
RSpec.describe "Workflow wait_state and resume" do
  it "halts at wait_state and resumes via send_event" do
    class ResumeCtx
      include Phronomy::WorkflowContext
      field :value, type: :replace, default: ""
    end

    app = Phronomy::Workflow.define(ResumeCtx) do
      initial :step1
      state     :step1,          action: ->(s) { s.merge(value: "#{s.value}:step1") }
      wait_state :awaiting_step2
      state     :step2,          action: ->(s) { s.merge(value: "#{s.value}:step2") }
      after :step1, to: :awaiting_step2
      after :step2, to: :__finish__
      event :proceed, from: :awaiting_step2, to: :step2
    end

    Phronomy.configure { |c| c.default_state_store = Phronomy::StateStore::InMemory.new }

    state = app.invoke({ value: "start" }, config: { thread_id: "t1" })
    expect(state.halted?).to be true

    final = app.send_event(:proceed, config: { thread_id: "t1" })
    expect(final.value).to eq("start:step1:step2")
  end
end
```
